DeepSeek Harness 插件入门：五款社区插件怎么配合

发表于2026-11-16|更新于2026-11-17|AI
|浏览量:

DeepSeek Harness（下文简称 DSH）装好以后，对话可以开始，文件树、技能、任务进度、外部工具和界面外观仍是出厂配置。社区插件分别补上这五块：侧边栏工作台、技能市场、任务板、MCP 连接器和换肤。profile 装错，或插件版本和宿主对不上，界面会保持原样。

本文面向已经能启动 dsh web 或桌面端的读者。读完可以决定这五款要不要装、装进哪个 profile，以及怎样确认已经生效。前四款的安装命令来自官方文档和各插件 2026-11-16 的说明；MCP 连接器来自 2026-11-17 的仓库说明与 npm。本文没有在当前环境执行这些命令。

五款都是社区项目，不随 @deepseek-ai/dsh 内核发布。安装前先看各自仓库的许可证和安全说明。

先分清插件和技能

插件和技能的安装位置不同。放错目录时，其中一种不会出现。

插件以 bundle 分发。bundle 是声明了 dsh.bundle 的 npm 包，包内的 cordis.patch.yml 用来插入或覆盖插件行。

实际启动的是一个 profile，目录在 $DSH_HOME/profiles/<名字>/。命令 dsh plugin --profile <名字> add <包> 把参数交给该目录里的 pnpm。包若声明了 bundle，会被写入 dsh.profile.bundles。层按列表顺序叠加，后面的层可以按 id 整行替换前面的配置。官方教程先用 dsh --profile <名字> --dump-config 确认层已经出现，再启动这个 profile。打包与安装说明

技能是另一条路径。一份技能可以是带 name 和 description 的 SKILL.md，也可以是扫描根目录顶层的一个 Markdown 文件。本地发现会查看：

  • 项目里的 .dsh/skills 和 .agents/skills
  • 用户目录下的 $DSH_HOME/skills 和 ~/.agents/skills
  • 配置里追加的目录

未设置 DSH_HOME 时，用户技能根是 ~/.dsh/skills。官方文件系统提供方会监视这些目录，下一次读取目录时就能看见文件变化。技能子系统说明、文件系统技能提供方

技能市场的说明更具体：安装技能后要重启 DeepSeek Harness。一场对话使用的是开始时确定的技能清单，所以新技能在重启之后的新会话里调用。官方的目录监视和插件要求的重启，两步都要做。

下图只画安装之后的两条落点。箭头表示数据落到哪里，不表示启动顺序。

    flowchart TD
    Profile["当前 profile"] --> Bundle["五个 bundle"]
    Bundle --> Ui["界面与宿主能力"]
    Market["技能市场或手写技能"] --> SkillRoot["$DSH_HOME/skills"]
    SkillRoot --> NewSession["重启后再开新会话"]

五款插件各管一件事

2026-11-16 查询 npm 时，@deepseek-ai/dsh 的 latest 是 0.2.2-rc.1，next 是 0.2.2-rc.3。下表前四款是当天各包的 latest；dsh-mcp-connector 是 2026-11-17 查询到的 0.2.110。这些号会变，安装前用 npm view <包名> version 再对一次。

插件 当天 npm 版本 主要补上的能力 装完先看哪里
dsh-better-sidebar 0.32.1 右侧栏与底部工作台：文件、可编辑预览、Git、任务、侧边对话 硬刷新后的侧边栏；设置里的侧边卡片
@montersy123/dsh-skill-market 2.1.0 浏览 SkillHub，把技能装进本机技能根 侧边栏中的 Skill Market

dsh-mcp-connector 0.2.110 连接 MCP Server：目录、授权、工具查找和排障 左侧「MCP连接器」
dsh-dream-skin 11.16.0 8 套 Mirage 皮肤、壁纸、强调色、主题包 设置 → 个性化皮肤

五款可以分开装。只需要可编辑文件树时，装侧边栏。只需要换外观时，装 dream-skin。只需要接入外部 MCP 时，装连接器，它不依赖 better-sidebar。技能市场从 SkillHub 另装技能；任务板按作者说明自带 mattpocock 的一套，并把任务铺开。两者可以同时安装。

侧边栏：dsh-better-sidebar

出厂右侧栏能看文件，预览通常是只读的，也没有与当前对话绑在一起的 Git 视图和底部终端布局。dsh-better-sidebar 在宿主原生右栏之外增加底部工作台，内置文件树、可编辑的 CodeMirror、Markdown / Mermaid 预览、Git 变更与只读提交图、子代理任务，以及仍标记为 beta 的侧边对话。终端来自 DSH 自己，这个插件不自带 PTY。作者开放了 ctx.betterSidebar，其他插件可以用同一套接口注册页面和文件查看器。项目说明

侧边栏版本要和宿主线对齐。0.32.1 需要 DSH 0.2.2-rc.2 或同线更新版本；停在 0.2.2-rc.1 时钉 dsh-better-sidebar@0.32.0。作者说明，0.x 的一个构建只服务一条宿主线。市场安装器会选择插件自己的 latest，旧宿主因此收到版本拒绝。

你的 DSH（2026-11-16） 应安装的侧边栏
0.2.2-rc.2 及以上，含当天 next 的 0.2.2-rc.3 dsh-better-sidebar@0.32.1
npm latest，当天是 0.2.2-rc.1 dsh-better-sidebar@0.32.0
0.2.1、0.2.0，以及 0.1.7 的 rc 和 stable 仓库 README 对照表中的钉版
0.1.7-alpha 没有兼容发布，先升级宿主

更老的宿主以 npm 上的同一份说明 和仓库 README 为准。

自 v0.23.0 起，它的文件路由不做工作区边界检查，能读写当前系统用户可以访问的路径。这些路由只有操作系统权限，没有额外的工作区围栏。HTML 预览默认放在不透明源的 sandbox iframe 里。设置中可以关闭这层 sandbox；该开关默认不启用，并带有警告，所以预览默认仍在 sandbox 中。插件不执行 git push、pull、fetch。

技能从哪来：dsh-skill-market

侧边栏负责看见项目文件。技能市场负责把技能装到本机，省去逐个复制。@montersy123/dsh-skill-market 在侧边栏放一个 Skill Market：按分类和关键词浏览 SkillHub，查看文件、版本、权限、指标和第三方安全扫描，再把选中的技能下载到 $DSH_HOME/skills/<handle>--<slug>/。装好的技能由 Harness 自己发现。停用这个插件之后，已经启用的技能仍留在原处。插件说明

启用和停用靠搬目录完成。停用时，整个技能目录被移到：

同级的 panel.json 保存收藏、已安装账本和类目偏好。installed.json 记录每个技能安装的版本。当前版本只读 $DSH_HOME/storages/...。从更早的 Local Storage 或 profile 目录升级时，要把旧的 data 目录搬过来，否则面板状态从空开始。已启用的技能仍在 $DSH_HOME/skills。

绿色「安全」标记只在 SkillHub 列出的检测方全部报告安全时出现。有一家给出可疑结论，面板就不显示标记。没有标记，表示检测方没有统一结论。插件作者写明：该项目与 SkillHub、腾讯、DeepSeek 没有隶属或背书关系；技能版权归原作者，插件的 MIT 许可不覆盖技能正文。浏览和安装需要访问 api.skillhub.cn。启用、停用和卸载不需要这台机器能访问该地址。宿主侧要求 Node.js 20 或更新。

任务板：dsh-mattpocock-skills-deck

技能装上之后，还需要看见这一轮做到哪一步。插件作者在仓库简介和 README 中写明，dsh-mattpocock-skills-deck 内置 mattpocock/skills v1.3.2 的 27 个技能。本文没有逐个清点。仓库简介里的「520 亿 token」「10 倍效率」是作者的宣传说法，不是本文的测量结果。

技能作者 Matt Pocock 在 AI Hero 上说明了这套技能的用法。入口是每个仓库先运行一次的 /setup-matt-pocock-skills。它确认三件事：issue 放在哪里、分诊标签叫什么、领域文档放在哪里，然后写成 docs/agents/ 下的 Markdown。后面的 triage、to-spec、to-tickets 和 wayfinder 都读这些文件。

插件界面包括任务板、地图卡片、单票详情、对话框胶囊栏，以及探索、实施两类新建需求。后端有 GitHub、GitLab 和本地 Markdown。本地 Markdown 在仓库简介里标为预览。插件作者写过，GitLab 后端目前缺少维护人力。GitHub 后端改 issue、建标签时，使用本机 gh 已登录账号在目标仓库中的权限：改票和建标签需要 push，改指派和流转标签需要 triage。只有只读权限的账号会被标成只读，浏览和刷新仍然可用。项目说明

版本号和 README 不一致，安装时要当场核对。2026-11-16，npm latest 是 1.9.0-beta.33，发布于 2026-11-01。同一天 GitHub main 的 package.json 写着 1.9.0-beta.34，且根包是 "private": true。README 中的安装命令写的是 @1.9.0-beta.34。应以 npm view dsh-mattpocock-skills-deck version 的结果为准。这是 beta 包，界面和流程还会变。

dsh-better-sidebar 当前的生态目录把它列为侧边栏页面插件。更早的 issue #646 记录过：当时面板通过 ctx.betterSidebar 注册，未安装 better-sidebar 时侧边栏模式不可用。该 issue 后来关闭，讨论里出现过改接原生右栏的记录。本文没有在 1.9.0-beta.33 的源码里复核当前入口。建议先装侧边栏，再装任务板。页面没有出现时，先确认侧边栏层已经加载。

MCP 连接器：dsh-mcp-connector

DSH 要调用外部数据和服务时，需要接上 MCP Server。dsh-mcp-connector 提供一个连接器市场：浏览目录，用 OAuth 2.0 PKCE、API Key、Streamable HTTP、stdio 或 mcpServers JSON 建立连接，再按名称查找当前范围内已启用连接的工具，并做连接诊断。作者写明，这里的「技能扩展」指 MCP 工具和 Prompt，它是连接器能力，不是一份独立的 DSH Skill。项目说明

2026-11-17，npm latest、GitHub main 的 package.json 和 Release 都是 0.2.110。作者在同一天的说明里写明：公共 Registry 已发布 118 条连接器描述，与随包的 4 张企查查卡片合并去重后，市场页可浏览 122 张卡片，覆盖 9 类。目录随 dsh-mcp-connector-registry 更新，不必等插件发版；页面上的数量以客户端刷新后的市场为准。首页推荐是固定的数据场景卡片，不是使用量排行。社区卡片不代表数据机构提供了官方 MCP。保存连接、发现工具和业务调用成功，要分开验证。

入口在左侧「MCP连接器」。DSH 0.2.0-rc.2 及以上使用官方 sidebar.panellist；0.1.x 使用兼容入口。侧栏可以隐藏，隐藏后从「设置 → 插件 → 插件配置 → MCP连接器」打开。它不依赖 dsh-better-sidebar。安装或升级后要完全重启：Desktop 退出应用再打开，dsh web 先停掉原进程再启动。只刷新网页不会加载新的后端插件。宿主侧要求 Node.js 20 或更高。package.json 里官方 MCP 客户端的 peer 范围是 ^0.1.1-rc.2 || >=0.2.0-rc.1 <0.3.0-0。

默认目录从 jsDelivr 读取公共 Registry；主源失败时再试 GitHub raw，然后回退到缓存或随包目录。把 catalogUrl 设成空字符串可以停用远程目录。stdio 会在本机启动进程，只连接可信命令。作者说明凭据写在本机 DSH storage，不进入市场目录、Git 仓库、页面、日志或对话历史。当前没有工具试运行。完整步骤见用户手册。

换肤：dsh-dream-skin

前面几款改变工作方式，这个插件改变外观。dsh-dream-skin 11.16.0 通过宿主的主题扩展点注册皮肤，包含 8 套 Mirage 预设：abyss、aurora、nebula、ember、midnight、ivory、mist、rose。同时提供壁纸、强调色叠加层、可导入导出的 *.dsh-theme.json 主题包，以及关闭玻璃模糊的低功耗模式。入口在 设置 → 个性化皮肤。作者把低功耗开关写成给多窗口掉帧准备的开关，并在说明里引用了自己的测量。那些 GPU 数字不是本文复测的。npm 包 11.16.0 的说明

安装来源以这个已发布的 npm 包为准。该版本的 homepage 和仓库字段指向 GitCode 上的 dsh-dream-skin。说明中写着原 GitHub 账号已被封禁，github: 简写不能再解析。本文没有另调 GitHub API 复核账号状态，安装时按插件说明避开旧的 GitHub 坐标。

npm 上的 peer 依赖覆盖到 0.3.0 之前的客户端包。宿主进入 0.3 时要重新核对兼容范围。这个包在 2026-11-16 当天发布，两种情况都要写死版本号：发布后的 24 小时内，pnpm 的 minimumReleaseAge 可能把不带版本号的安装静默解成上一版；从 9.x 升上来的旧 profile 中，^9 覆盖不到 11.x。

桌面端还有一条单独限制。插件说明记录：官方 Electron 桌面应用独占名为 desktop 的 profile，CLI 会拒绝 dsh plugin --profile desktop ...，报错大意是该 profile 只能由应用管理。技能市场和任务板的 README 仍然写了 --profile desktop。先确认自己启动的是哪一个入口。命令被拒绝时，改用应用内的插件安装界面，或按 dream-skin 文档在该 profile 目录里安装指定版本。

按这个顺序安装

任务板和技能市场的界面都落在侧边区域，所以先装侧边栏。MCP 连接器和换肤可以单独安装，顺序不限。下图是建议的安装顺序。

装完先确认层已经出现，再重启。dump-config 的输出里应有各包名字构成的层标记，官方示例的形式是 # == <包名>。

better-sidebar 还要求浏览器硬刷新，macOS 上是 Command+Shift+R。如果 dsh web 在安装前已经运行，旧进程仍使用安装前的组合：先停掉，再启动，然后刷新。技能市场写入 $DSH_HOME/skills 的技能，按该插件说明重启对应 profile，再开一个新会话。

从 git 地址安装时，pnpm 10 及以上默认不运行依赖的 prepare 脚本，源码包可能没有构建产物。官方说明把放行构建脚本视为在本机安装期执行对方代码，并建议钉住 commit。这五款都有已发布的 npm 包，日常安装使用上面的版本号。MCP 连接器作者另外提供一条从 GitHub 拉取的安装脚本；采用它之前先阅读脚本内容。本文示例使用钉好的 npm 版本。官方对 git 安装的说明

使用时的边界

这五款插件装上之后，DSH 进程会执行第三方代码。只从 npm 上的确定版本安装，并在 --dump-config 里确认层名与包名一致。

  • 侧边栏的文件接口能访问工作区以外、当前系统用户有权限的路径。本机 DSH 只给可信任的网络和会话使用。
  • 技能市场安装的是 SkillHub 上的他人作品。绿色标记表示列出的检测方当时都报告了安全，安装前仍要阅读技能自己的 SKILL.md。卸载和版本回退会删除技能目录，恢复时需要重新下载。
  • 任务板的 GitHub 后端使用本机 gh 的身份修改 issue。只在账号拥有该仓库权限，并且接受插件代为改票时启用。
  • MCP 连接器会保存第三方服务的凭据，并用 stdio 启动本机进程。只连接可信的 Server 和命令。默认会向 jsDelivr 请求公共目录。作者说明当前没有工具试运行，发现到工具不等于业务调用已经成功。
  • 换肤可以请求图片 URL，出厂说明里预填了必应每日壁纸接口。使用本地图或渐变时，可以避开外网图片。低功耗模式会关闭玻璃模糊。作者给出的 GPU 占用数字没有在本文环境复测。

同名技能谁生效，要看官方注册表的合并结果：离当前 scope 更近的层胜出；同一层内部再按发现顺序决定。后安装的技能不一定覆盖先安装的技能。技能子系统说明

装完没有变化时先查这几项

侧边栏报版本不兼容

对照 dsh --version。0.2.2-rc.1 配 dsh-better-sidebar@0.32.1 会按作者的兼容表被拒绝。改钉 0.32.0，或把宿主升到 0.2.2-rc.2 及以上再装 0.32.1。

命令成功，界面仍是旧的

看 --dump-config 里有没有新层。没有层，说明包已经装进依赖，但没有 dsh.bundle，或装到了另一个 profile。有层而页面没变，常见原因是旧的 dsh web 进程仍在运行，或浏览器保留了旧的前端资源。重启进程并硬刷新。

技能市场里的技能，当前对话不会用

技能文件可以已经在 $DSH_HOME/skills。按插件说明重启对应 profile，再新开一轮。浏览失败时，先确认这台机器能访问 api.skillhub.cn。

任务板不在侧边栏里

确认 better-sidebar 已装进同一个 profile，并且该页面没有在它的设置里被关掉。本文没有验证 1.9.0-beta.33 在缺少 better-sidebar 时是否还有别的入口。

左侧没有 MCP连接器
